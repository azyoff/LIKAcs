# Update flow: GitHub Release → one click → every PC

Website: <http://likaapps.com>

## 1. Publishing a release

```
[Tag vX.Y.Z] -> release.yml (windows-latest)
   VAC guard + 92 unit tests + self-test + real Tk render of all 5 windows
   PyInstaller -> LIKAcs.exe, LIKAcs-Setup.exe, optional shortcut exes
   SHA256SUMS.txt          (real digests of every built file)
   latest.json             (version, notes, asset URL, SHA-256, size)
                     |
                     v
[GitHub Release] one user-facing .exe: LIKAcs.exe
   attached: LIKAcs.exe, latest.json, SHA256SUMS.txt, README.md, LICENSE
   Actions artifact only: LIKAcs-Setup.exe (silent IT rollout)
```

`latest.json` is generated by `scripts/build.py --tag vX.Y.Z` from the real
checksums. It contains:

```json
{
  "schema": 1,
  "product": "LIKAcs",
  "version": "1.1.0",
  "tag": "v1.1.0",
  "notes": "...",
  "html_url": ".../releases/tag/v1.1.0",
  "checksums_url": ".../releases/download/v1.1.0/SHA256SUMS.txt",
  "assets": {
    "LIKAcs.exe": {"url": ".../LIKAcs.exe", "sha256": "...", "size": 12345678}
  }
}
```

## 2. One-click self-update (what the user actually does)

Click **Update LIKAcs** once — in the header, Updates tab, tray right-click
menu, About dialog or the Station Agent window. No downloading, renaming,
copying or manual restart.

```
[SelfUpdater.check()]
   GET https://github.com/azyoff/LIKAcs/releases/latest/download/latest.json
   (no API rate limits; GET /releases/latest via the API is the fallback)
   version_is_newer(tag, VERSION)  ->  up to date? stop, nothing changes
                     |
                     v
[download_verified()]
   stream LIKAcs.exe from the Release asset URL
   SHA-256 must equal the manifest digest
   size must equal the manifest size
   SHA256SUMS.txt must agree (when reachable)
   any mismatch -> discard, friendly error, NOTHING on disk is changed
                     |
                     v
[stage_swap()]  (frozen Windows build only; never swaps python.exe)
   write %TEMP%\LIKAcs\likacs-selfupdate-<pid>.cmd
   launch it with CREATE_NO_WINDOW, then exit immediately
                     |
                     v
[.cmd helper]
   wait for the running PID to exit (tasklist loop)
   copy current exe -> LIKAcs.exe.bak
   move staged LIKAcs.exe.new -> LIKAcs.exe
   start /wait LIKAcs.exe --version     <-- boot check
   if errorlevel 1 -> restore .bak, relaunch, write .update-failed marker
   else -> relaunch with the original command line
```

Games are never terminated by an update, so a live match is never interrupted.
The `.bak` is kept next to the exe as an extra manual recovery option.

## 3. Optional cafe-wide push (advanced)

The Control Center's **Push update to ALL Station PCs** button downloads the
same verified exe once and streams it over the signed LAN:

```
POST /update-begin   {version, size, sha256, filename}
POST /update-chunk   {id, offset, data(base64)}  x N   (512 KiB chunks)
POST /update-finish  {id, restart}
                     |
                     v
[Each Station Agent]
   verifies size + SHA-256 again, discards on mismatch
   stages %APPDATA%\LIKAcs\updates\LIKAcs-vX-....exe.new
   pending-update.json saved, heartbeat advertises staged version
   optional: writes a .cmd swap helper and exits silently
```

or simply click **Update LIKAcs** on each PC — each one fetches its own
verified copy from GitHub.

## Why a swap helper

Windows locks a running `.exe`; it cannot be overwritten in place. The helper
is a plain batch script generated by `update.build_swap_script()` (for LAN
pushes) or `selfupdate.build_self_swap_script()` (for one-click updates). No
installer, no service, no elevation. The one-click variant additionally runs a
boot check and rolls back automatically.

## Safety

* The manifest digest, the asset size **and** `SHA256SUMS.txt` must agree.
* Every station independently re-verifies hash and size before staging.
* All LAN traffic is HMAC-signed and replay-protected (see [PORTS.md](PORTS.md)).
* A failed transfer is deleted and reported; nothing is executed automatically
  until verification succeeds.
* A version check that finds no newer release changes nothing at all, so the
  button is safe to click at any time.
* `latest.json` and `SHA256SUMS.txt` are attached to every release before it is
  marked "latest", so the updater can always find them.

## Manual / offline updates

Copy the verified `LIKAcs.exe` to each PC (USB stick) and replace it while
LIKAcs is closed; the next start picks up the new version. The Control Center
shows the installed version in the About dialog, header and Updates tab.
`LIKAcs.exe --check-update` prints the release information as JSON without
installing anything; `LIKAcs.exe --update` performs the same one-click flow
headlessly.
